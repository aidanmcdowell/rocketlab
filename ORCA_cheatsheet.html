1. Strategy for Hiring Team (Engineering Leads & OR Analysts)

↑ Back to Top
Who You Are Talking To & What They Value
The ORCA group at SPA does not build generic web apps — they build defense simulation engines that Pentagons brief on.

Your interviewers will consist of Senior Software Engineers, Modeling & Simulation Developers, and Operations Research Analysts. Their priorities are fundamentally different from Big Tech:

  • Software Serving Analysis: Frame your code as an enabler for decision-makers. OR analysts run Monte Carlo campaigns with 10,000 runs — if your simulation loop is non-deterministic or leaks memory, the entire fleet acquisition brief fails.
  • Data Integrity > Clever Hacks: Prefer clean, readable, defensively validated OOP classes over obscure one-line functional tricks.
  • Onsite & Clearance Readiness: Reaffirm comfort with daily onsite collaboration in San Diego. Classified wargames and ITAR-restricted radar data cannot leave SCIFs.
  • Language Strategy: Use Java or C#. Avoid C++ on the whiteboard. The team develops primarily in Java and C#. Both have identical garbage collection, reference semantics, and standard collections. Avoid C++ pointer syntax and manual memory allocation under whiteboard pressure.

3. The 5-Step Incomplete-Problem Whiteboard Execution Framework

↑ Back to Top

SPA interviewers typically give you an incomplete class hierarchy or a buggy method and ask: "Complete this method so our radar tracker correctly handles this scenario." Follow this exact 5-step framework:

Step 1: Read & Trace Aloud (Don't Write Code Yet!)

Spend the first 60 seconds reading the given code aloud:

  • "I see we have an abstract Track base class with common telemetry fields."
  • "The TrackManager maintains an internal map, and we have an unimplemented ingest(Track track) method."
  • "Let's identify the contract: what arguments arrive, what should be returned, and what side effects are expected."
Step 2: Clarify Constraints & Edge Cases

Ask 2–3 sharp questions that prove defense modeling maturity:

  • "Can tracks arrive out of order, or with duplicated track IDs?" (Answer: yes, duplicate IDs should overwrite with newest kinematics).
  • "What are the valid operational boundaries for latitude and longitude?" (-90 to +90 lat, -180 to +180 lon).
  • "What is the expected scale — 10 tracks per second or 50,000 in a batch simulation?" (Influences choosing HashMap vs ConcurrentHashMap).
Step 3: Identify the Missing Pattern / Gap

Diagnose what's missing in the provided code:

  • Missing Polymorphism: Are they using a brittle if (type == "RADAR") else if (type == "SONAR") chain? Say: "This violates the Open/Closed Principle — we should use a Factory/Registry pattern."
  • Wrong Data Structure: Are they sorting an ArrayList every tick? Say: "Sorting an ArrayList is O(n log n) every frame. A PriorityQueue gives us O(log n) insertions and O(1) peek."
  • Missing Defensive Guards: No null checks or coordinate range checks.
Step 4: Implement Cleanly with Helper Methods

Write clean, structured code on the board. Break large logic into readable helpers:

// Clean structure
public void ingest(Track track) {
    if (!isValid(track)) return; // Guard clause
    activeTracks.put(track.getTrackId(), track); // Upsert
}
Step 5: Dry-Run Edge Cases with Concrete Values & State Big-O

Before saying you're done, trace 3 edge cases on the board:

  1. track == null → caught by guard clause, no NullPointerException.
  2. Duplicate trackId → activeTracks.put() cleanly overwrites previous record, size stays constant.
  3. Out-of-bounds coordinates (e.g. lat = 105.0) → rejected before reaching internal collection.
  4. State Time & Space Complexity: "Ingestion is O(1) amortized lookup/insert for HashMap, O(n) space where n is active track count."

4. The 3 SPA Defense Modeling Problem Archetypes

↑ Back to Top

Archetype A: PriorityQueue Threat Allocator (Min-Heap by TTI)

The Problem: DDG-79 has 15 hostile contacts. You must allocate weapons to the most urgent threats first (lowest Time to Impact = highest danger).

// Java Implementation — Target Interview Code
import java.util.*;

public class ThreatEvaluator {

    public List<Track> getHighestPriorityThreats(List<Track> tracks, int k) {
        // 1. Guard against null, empty list, or non-positive k
        if (tracks == null || tracks.isEmpty() || k <= 0) {
            return Collections.emptyList();
        }

        // 2. Min-Heap: smallest TTI comes off first
        PriorityQueue<Track> pq = new PriorityQueue<>(
            (a, b) -> Double.compare(a.getTimeToImpact(), b.getTimeToImpact())
        );

        // 3. Filter: only active, un-neutralized hostiles
        for (Track t : tracks) {
            if (t != null && t.isHostile() && !t.isNeutralized()) {
                pq.offer(t);
            }
        }

        // 4. Extract top-K threats
        List<Track> result = new ArrayList<>();
        while (!pq.isEmpty() && result.size() < k) {
            result.add(pq.poll());
        }

        return result;
    }
}
Analyst Discussion Points for Archetype A
  • Complexity: Building the heap takes O(n log n). Extracting k elements takes O(k log n). Total time is O(n log n), space is O(n).
  • Monte Carlo $P_k$ Formula: If the analyst asks how weapons resolve, state: P_k_total = 1 - (1 - P_k_single)^n, where n is rounds fired. For SM-6 ($P_k = 0.84$), a 2-shot salvo yields $1 - (0.16)^2 = 97.44\%$.

Archetype B: Track Ingestion & Boundary Filter (Upsert & Validation)

The Problem: Write ingest(Track track) to validate incoming radar tracks against geographic boundaries and store them in the active map.

// Java Implementation
public class TrackManager {
    private final Map<String, Track> activeTracks = new HashMap<>();

    public void ingest(Track track) {
        // 1. Null check guard
        if (track == null) return;

        // 2. Empty ID guard
        if (track.getTrackId() == null || track.getTrackId().trim().isEmpty()) return;

        // 3. Boundary validation
        double lat = track.getLat();
        double lon = track.getLon();
        if (lat < -90.0 || lat > 90.0 || lon < -180.0 || lon > 180.0) return;

        // 4 & 5. Upsert: overwrites existing record if present, inserts if new
        activeTracks.put(track.getTrackId(), track);
    }

    public Map<String, Track> getActiveTracks() {
        return Collections.unmodifiableMap(activeTracks);
    }
}

Archetype C: Extensible Sensor Parser (Factory / Registry Pattern)

The Problem: Replace a fragile if/else-if parser with an extensible design that adheres to the Open/Closed Principle.

// Java Implementation
public interface SensorParser {
    Track parseRecord(byte[] payload);
}

public class SensorIngestionService {
    // Registry of parsers by sensor type
    private final Map<SensorType, SensorParser> parsers = new HashMap<>();
    private final Map<String, Track> activeTracks = new ConcurrentHashMap<>();

    public void registerParser(SensorType type, SensorParser parser) {
        if (type != null && parser != null) {
            parsers.put(type, parser);
        }
    }

    public void ingest(SensorType type, byte[] payload) {
        SensorParser parser = parsers.get(type);
        if (parser == null) {
            throw new IllegalArgumentException("No parser registered for: " + type);
        }

        Track track = parser.parseRecord(payload);
        if (track != null && track.isValid()) {
            activeTracks.put(track.getTrackId(), track);
        }
    }
}

6. Defense Domain Primer for Software Engineers

↑ Back to Top
Terminology OR Analysts Use Every Day
  • C5ISR: Command, Control, Communications, Computers, Cyber, Intelligence, Surveillance, and Reconnaissance. The software layer connecting radars to missiles.
  • AN/SPY-6 (AMDR): Air and Missile Defense Radar installed on Flight III Arleigh Burke destroyers (DDG-79 class). High sensitivity S-band radar capable of tracking ballistic and hypersonic targets simultaneously.
  • ASCM vs HGV: ASCM (Anti-Ship Cruise Missile, Mach 0.8–2.5, sea-skimming). HGV (Hypersonic Glide Vehicle, Mach 5+, high altitude, erratic atmospheric maneuvers requiring immediate weapon allocation).
  • Magazine Economy: You cannot fire an SM-6 ($4.3M) at every $20,000 drone. Defense models simulate multi-layer weapons: electronic jamming (EW) → close-in ESSM / RAM → kinetic SM-6.
