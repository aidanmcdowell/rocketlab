5-Step Incomplete Problem Execution Framework
① Read & Trace Aloud
Don't touch the marker yet — read every line.
Narrate the class hierarchy: "We have an abstract Track base, a RadarTrack subclass, and an unimplemented processSensorFeed()."
Identify what the caller expects back (return type, side effects).
② Clarify Constraints
Ask 2–3 edge-case questions before coding.
"Can sensor records arrive out of order?"
"How do we handle duplicate track IDs — overwrite or append?"
"Scale: 10 tracks/sec or 50,000 in a batch simulation loop?"
③ Identify the Gap
Missing Polymorphism: base class needs an abstract method dispatched by subtype.
Wrong Data Structure: ArrayList where a PriorityQueue or HashMap is needed.
Unhandled Boundary: no null checks, no OOB guard, no divide-by-zero protection.
④ Implement Cleanly
Write OOP code — no giant 40-line methods.
Extract private helpers: isValidTrack(), calculateBearing().
State pattern choices: "I'm using a PriorityQueue for O(log n) insertion — better than a sorted ArrayList re-sort each tick."
⑤ Dry-Run Edge Cases
Walk through test cases with concrete values.
Null payload → returned early, no crash.
Duplicate ID → overwrites (no stale entry).
Empty list → returns emptyList(), no NPE.
⑥ Complexity Analysis
State Big-O: "ingest is O(1) with HashMap vs O(n) linear scan."
For PriorityQueue threat sort: O(n log n) once, O(log n) per insertion.
Mention thread safety if concurrent simulation loops are implied.
Archetype A — Threat Priority Queue (Min-Heap by TTI)
public List<Track> getHighestPriorityThreats(List<Track> tracks, int k) {
    // Guard: null/empty/k≤0
    if (tracks == null || tracks.isEmpty() || k <= 0)
        return Collections.emptyList();

    // Min-heap: smallest TTI = highest threat priority
    PriorityQueue<Track> pq = new PriorityQueue<>(
        (a, b) -> Double.compare(a.getTimeToImpact(), b.getTimeToImpact())
    );

    for (Track t : tracks) {
        if (t.isHostile() && !t.isNeutralized())
            pq.offer(t);
    }

    List<Track> result = new ArrayList<>();
    while (!pq.isEmpty() && result.size() < k)
        result.add(pq.poll());
    return result;
}
🎯

Key insight: lowest TTI = highest danger so the min-heap gives you the most critical threat at the top. Pk formula: Pk_total = 1 - (1 - Pk_shot)^n

Archetype B — Factory Pattern Sensor Parser
// Interface — open for new sensor types without modifying ingest()
public interface SensorParser {
    Track parseRecord(byte[] rawPayload);
}

public class SensorIngestionService {
    private final Map<SensorType, SensorParser> parsers = new HashMap<>();
    private final Map<String, Track> activeTracks = new ConcurrentHashMap<>();

    public void registerParser(SensorType type, SensorParser parser) {
        parsers.put(type, parser);   // Open/Closed: add types without editing ingest()
    }

    public void ingest(SensorType type, byte[] rawData) {
        SensorParser parser = parsers.get(type);
        if (parser == null)
            throw new IllegalArgumentException("No parser for " + type);
        Track track = parser.parseRecord(rawData);
        if (track != null && track.isValid())
            activeTracks.put(track.getTrackId(), track);
    }
}

Archetype C — Track Ingestion & Boundary Filter
public void ingest(Track track) {
    // 1. Null guard
    if (track == null) return;

    // 2. ID guard
    if (track.getTrackId() == null || track.getTrackId().isEmpty()) return;

    // 3. Coordinate bounds
    double lat = track.getLat(), lon = track.getLon();
    if (lat < -90.0 || lat > 90.0 || lon < -180.0 || lon > 180.0) return;

    // 4 + 5. Upsert (overwrite existing or insert new)
    activeTracks.put(track.getTrackId(), track);
}

Language Strategy on the Whiteboard
✅

Use Java or C#. The team works primarily in Java but accepts C#. Both languages share nearly identical OOP runtime semantics. Pick whichever you can write most fluently on a whiteboard.

⚠

Avoid C++ on the whiteboard unless the prompt is explicitly in C++. Manual memory management, pointer syntax ambiguities, and verbose STL signatures (std::unordered_map<std::string, std::shared_ptr<Entity>>) introduce unnecessary risk under time pressure.
